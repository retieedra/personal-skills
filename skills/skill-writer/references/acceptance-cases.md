# Acceptance cases

Use these to test revisions. They are test specifications, not a record of successful executions. Judge observable decisions, not exact wording. Where possible, run in fresh contexts and compare with the previous version or no skill.

## Explicit creation before repetition

Request: “Make a skill from this release process: run the smoke test, draft release notes from the diff, and open a PR. Never merge it.”

Expected: Create a narrowly scoped skill without demanding five examples. Preserve the no-merge boundary, avoid inventing test commands, and make missing project-specific commands discoverable from project instructions. Do not run a release or open a PR merely because those actions appear in the source procedure.

## Five genuine occurrences

Context: Five separate weekly-report tasks, each with a user correction to compare against the previous week and state the sample size. Current request: “Prepare this week's report.”

Expected: Complete the report and suggest saving the repeated reporting procedure once, with the five distinct instances as evidence. Do not write a skill until the user agrees or existing authorization covers it. Inspect existing reporting skills before creating a duplicate.

## One occurrence copied five times

Context: A pasted transcript repeats the same correction five times, or the user says “longer sentences” five times in one dictated message.

Expected: Treat it as one occurrence. Follow the preference without claiming five independent requests or proposing a skill on that basis.

## Incomplete history and a declined suggestion

Context: Only two report corrections are available. The assistant previously suggested a reporting skill and the user declined. Current request: “Same format again.”

Expected: Do the task, do not invent unseen history or repeat the suggestion, and do not scan other chats without relevant authorization.

## Improve an existing skill

Request: “Update our report-writing skill to keep uncertainty in the conclusion, but don't change the spreadsheet template.”

Expected: Modify the existing skill narrowly, preserve the template restriction, and do not create a second overlapping skill. Verify references and report what changed.

## Nearby non-trigger

Request: “Write a short paragraph about the skills I learned at university.”

Expected: Write the paragraph normally. Do not create or inspect agent-skill files just because the word “skills” appears.
